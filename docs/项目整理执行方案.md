## 一、需求背景

当前项目在 `3266d16 feat: Excel 驱动测试框架 — 新架构 + 旧文件清理` 重构后，仍存在以下问题：

1. **冗余代码**：多个文件中有重复的用例加载/执行逻辑（`executor.py`、`run_cases.py`、`test_excel_runner.py` 三份）
2. **日志噪音**：Info 级别的飞书加载日志过多，干扰关键信息读取
3. **不必要的检查**：测试文件预置检查阻塞了不依赖测试文件的用例执行
4. **命名歧义**：部分文件和类命名不够清晰

---

## 二、需求清单

### 需求 1：项目结构整理 → 清理冗余代码 + 文件命名消除歧义

| 子项 | 描述 | 当前问题 |
|------|------|----------|
| 1.1 | 删除 `engine/executor.py` | `ExcelRunner` 类与 `test_excel_runner.py` 内联的 `_dispatch_step` 功能高度重复，唯一引用方 `run_cases.py` 也将删除 |
| 1.2 | 删除 `scripts/run_cases.py` | 用例加载+执行逻辑与 `test_excel_runner.py` 大量重复，作为非 pytest 入口功能完全被 `test_excel_runner.py` 覆盖 |
| 1.3 | 删除根目录 `test.txt` | 无关联文件 |
| 1.4 | 删除 `boox_automation/pytest.ini` | 与项目根 `pytest.ini` 产生混淆，pytest 默认读取根目录的配置 |
| 1.5 | `tests/helpers.py` 保持原位 | 被 `conftest.py` fixture 和 `test_excel_runner.py` 使用，作为测试辅助模块位置合理 |

### 需求 2：降低飞书操作日志等级到 DEBUG

| # | 日志内容关键词 | 所在文件 | 当前等级 | 目标等级 |
|---|---|---|---|---|
| 2.1 | `已从飞书读取 sheet '...': N 行` | `core/feishu.py:138` | `INFO` | `DEBUG` |
| 2.2 | `已从飞书加载 N 个元素定义` | `engine/elements.py:362` | `INFO` | `DEBUG` |
| 2.3 | `已从飞书加载 N 个预期结果定义` | `engine/elements.py:411` | `INFO` | `DEBUG` |
| 2.4 | `已从缓存加载 N 个元素定义` | `engine/elements.py:313` | `INFO` | `DEBUG` |
| 2.5 | `已从缓存加载 N 个预期结果定义` | `engine/elements.py:434` | `INFO` | `DEBUG` |

**原因**：这些日志是正常启动过程信息，不是用户关心的关键状态。降级后终端输出更干净，排查问题时仍可通过 `--log-cli-level=DEBUG` 查看。

### 需求 3：降低 Appium 自动拉起日志等级到 DEBUG

| 日志内容 | 所在文件 | 当前等级 | 目标等级 |
|---|---|---|---|
| `检测到 Appium 未监听 127.0.0.1:4723，尝试自动拉起：...` | `core/health.py:46` | `WARNING` | `DEBUG` |

**原因**：自动拉起是正常的自动恢复行为，不应以 WARNING 级别呈现。拉取失败时已有 `RuntimeError` 兜底抛出。

### 需求 4：注释"测试文件检查"逻辑

**问题**：当前 `check_test_files()` 方法强制要求设备 `/sdcard/笔记自动化测试文件/` 下存在 6 个预置子目录，缺失则直接 `RuntimeError` 中断。这导致不依赖测试文件的用例（如笔记创建类）无法单独运行。

**方案**：注销相关逻辑，不再要求预置测试文件目录。

| 文件 | 位置 | 操作 |
|------|------|------|
| `devices/info.py` | `check_test_files()` 方法体（L217-231） | 注销方法体，保留方法签名（避免调用方报错） |
| `conftest.py` | `pytest_sessionstart()` 中 `devices.check_test_files(device_id)` 调用（L190） | 注销调用 |
