# 笔记自动化测试 — 使用指南

> 本文档面向**无编程经验的测试人员**，用最通俗的语言解释：怎么写测试用例、怎么定义页面元素、项目文件是干什么的。
> **规则：每个章节顶部先给示例，再讲规则。**

---

## 一、两分钟快速理解

这个项目做一件事：**把 Excel 里的测试步骤，自动在设备上执行**。

```
Excel 测试用例（你写的）          自动化程序（自动跑的）
─────────────────────────       ────────────────────────
操作步骤：                       →  打开笔记应用
1.点击【笔记】                    →  点击"笔记"图标
2.检查【笔记首页引导UI】           →  检查首页所有元素是否正常
3.点击【创建笔记】                 →  点击创建按钮
4.点击【手写笔记】                 →  选择手写笔记
```

**你需要维护两个 Excel 文件：**

| 文件 | 干什么用 | 类比 |
|---|---|---|
| `test_cases.xlsx` | 写测试用例：先做什么、再做什么 | 就像"测试操作手册" |
| `elements.xlsx` | 告诉程序每个按钮/文字怎么找到 | 就像"页面元素通讯录" |

## 二、测试用例怎么写（test_cases.xlsx）

### 示例（先看这个）

```
优先级：P0
标题：未登录-创建手写笔记
所属模块：笔记首页
前置条件：
    1. 新设备或重置设备后未打开过【笔记】
    2. 没有登录过账号
    3.【海外设备执行】

操作步骤：
    1.设备桌面点击【笔记】应用
    2.检查笔记首页引导UI
    3.点击【创建笔记】笔记按钮
    4.检查创建二级菜单UI
    5.点击创建菜单中【手写笔记】
    6.检查手写笔记创建页面UI
    7.创建笔记页面点击【创建】按钮
    8.点击【退出手写笔记】
    9.检查手写笔记命名

预期结果：
    1.笔记首页引导图标显示正常
    2.创建菜单弹窗显示【手写笔记】【文本笔记】【会议笔记】【无边笔记】
    3.手写笔记创建成功，笔记列表显示命名
```

### 列说明

Excel 中以下列会被程序读取：

| 列 | 列名 | 说明 | 可以不填？ |
|---|---|---|---|
| G | 标题 | 用例名称，简短描述要测什么 | **必填** |
| H | 优先级 | P0（核心）/ P1（重要）/ P2（次要） | 建议填写 |
| D | 所属模块 | 用例属于哪个页面，如"笔记首页" | 建议填写 |
| I | 前置条件 | 在什么设备上执行、需要什么环境 | 可为空 |
| J | 操作步骤 | 一步步怎么做，用【】标记要操作的按钮 | **必填** |
| K | 预期结果 | 每一步期望看到什么 | 建议填写 |

其他列（A 维护人、B 用例类型、C 编号等）程序不读取，可自由填写。

### 操作步骤写法

**核心规则：用 `【】` 把要操作的按钮/文字括起来，程序会自动找到它。**

每一步前面加数字编号（1. 或 1、都可以），换行分隔。

```
1.点击【笔记】                      → 程序：找到"笔记"，点击它
2.检查【笔记首页引导UI】             → 程序：检查首页所有引导元素是否存在
3.点击创建菜单中【手写笔记】         → 程序：找到"手写笔记"，点击它
4.输入【笔记标题】输入test          → 程序：在标题输入框里输入"test"
5.长按【笔记条目】                  → 程序：长按笔记条目
```

### 动作关键词

程序通过**动作关键词**判断要做什么：

| 写在步骤里的词 | 程序做的事 | 示例 |
|---|---|---|
| `点击` `打开` `进入` `选择` `双击` `退出` `返回` `清空` `确认` | 点击这个元素 | `点击【创建笔记】` |
| `检查` `查看` `校验` | 检查元素是否存在 | `检查【笔记首页引导UI】` |
| `输入` | 在输入框里填内容 | `输入【笔记标题】测试名称` |
| `长按` | 长按这个元素 | `长按【笔记条目】` |
| `滑动` | 在屏幕上滑动 | `向上滑动` |

**规则：** 如果写了 `【xxx】` 但没写动作词，默认当"点击"处理。如果什么都没写，这一步跳过。

### 输入动作的特殊规则

输入动作的步骤文本中可以写第二个 `【】` 来引用前置条件中定义的变量：

```
前置条件：【输入用户名-testuser】

操作步骤：
1.输入【用户名输入框】【用户名】    → 程序会把 "testuser" 填入输入框
```

如果步骤文本中直接写了"输入XXXX字符"，程序会提取 X 作为输入内容：
```
1.输入【笔记标题】输入test字符      → 程序填入 "test"
```

### 前置条件写法

前置条件放在 `【】` 中，支持以下几种：

**条件型（根据设备自动判断是否执行）：**

| 写法 | 含义 | 例子 |
|---|---|---|
| `【国内设备执行】` | 仅国内设备跑这条用例 | 你的设备是海外版 → **自动跳过** |
| `【海外设备执行】` | 仅海外/全球设备跑 | 你的设备是国内版 → **自动跳过** |
| `【平板设备执行】` | 仅平板设备跑 | 阅读器 → **自动跳过** |
| `【阅读器设备执行】` | 仅阅读器设备跑 | 平板 → **自动跳过** |
| `【黑白设备执行】` | 仅黑白屏设备跑 | 彩屏 → **自动跳过** |
| `【彩色设备执行】` | 仅彩屏设备跑 | 黑白屏 → **自动跳过** |

**版本型（根据固件版本判断）：**

| 写法 | 含义 |
|---|---|
| `【4.2-版本执行】` | 设备固件版本 ≥ 4.2 才执行 |

**变量型（定义输入值）：**

| 写法 | 含义 |
|---|---|
| `【输入用户名-testuser】` | 定义一个叫"用户名"的变量，值是"testuser" |

**多条件可同时写，换行分隔：**
```
【平板设备执行】
【4.2-版本执行】
【输入笔记名-测试笔记】
```

### 优先级筛选

程序默认只跑 P0 用例。如需跑其他优先级，修改 `test_excel_runner.py` 文件第 44 行：

```python
PRIORITY_FILTER = "P0"   # 改成 "" 跑全部，改成 "P1" 跑 P1+P2
```

| 设置值 | 跑的用例 |
|---|---|
| `"P0"` | 仅 P0 |
| `"P1"` | P1 + P2 |
| `"P2"` | 仅 P2 |
| `""` | 全部 |

## 三、元素怎么定义（elements.xlsx）

### 示例（先看这个）

一个完整的元素定义（表格中一行）：

```
key:        笔记首页.创建笔记按钮
match:      创建笔记
locator:    //android.widget.TextView[@resource-id="com.onyx.android.note:id/tv_create"]
action:     click
operation:  点击首页的创建笔记按钮，弹出创建类型选择菜单
index:      1
```

有了这条定义，当测试步骤中写 `点击【创建笔记】` 时，程序就能找到这个按钮并点击。

### Excel 结构

`elements.xlsx` 是一个 Excel 文件，包含多个 **Sheet（工作表）**。

- **每个 Sheet = 一个页面**。比如"笔记首页"的所有元素放在 `note_home` sheet 中。
- Sheet 名称可以随便取，但建议用英文，如 `note_home`、`note_handwritten`。

当前已有的 Sheet：

| Sheet 名 | 对应的页面 |
|---|---|
| `note_home` | 笔记首页（创建按钮、笔记列表、引导弹窗等） |
| `note_handwritten` | 手写笔记编辑页（退出按钮、工具栏等） |
| `note_text` | 文本笔记编辑页 |
| `note_infinite` | 无边笔记编辑页 |
| `note_meeting` | 会议笔记编辑页 |
| `system` | 系统级通用元素（Dock 栏、存储入口等） |

### 列说明

| 列 | 列名 | 说明 | 必填？ | 示例值 |
|---|---|---|---|---|
| A | `key` | 元素唯一 ID，格式：`页面.元素名` | **必填** | `笔记首页.创建笔记按钮` |
| B | `match` | 匹配文本，步骤中 `【】` 里的字 | **必填** | `创建笔记` |
| C | `locator` | 定位方式，通常是 XPath 或文字 | **必填** | `//*[@resource-id="..."]` |
| D | `action` | 动作类型，覆盖步骤中自动推断的动作 | 建议填写 | `click` |
| E | `operation` | 这个元素是干什么的（日志用） | 建议填写 | `点击首页的创建按钮` |
| F | `index` | 同类元素的序号，从 0 开始 | 选填 | `1` |
| G | `dismiss_with` | 关闭弹窗时需要额外点击的按钮 key | 选填 | `手写笔记.工具条确认` |
| H | `overrides` | 不同设备上的适配规则 | 选填 | 见下方说明 |
| I | `checks` | 需要同时检查多个子元素 | 选填 | 见下方说明 |

### match 列 — 匹配文本

**这个是最重要的列。** 程序通过它把步骤中的 `【xxx】` 和元素关联起来。

```
步骤中写：【创建笔记】
match 列的值：创建笔记        → 匹配成功！
```

**规则：**
- match 的值要和步骤中 `【】` 里的文字**完全一致**
- 如果多个元素的 match 相同，程序会根据"所属模块"列自动选择最匹配的
- 如果找不到匹配，会打印警告，这一步会被跳过

### locator 列 — 定位方式

支持两种写法：

**写法一：直接写界面上的文字（推荐，最简单）**
```
locator: 创建笔记
```
程序会自动在页面上搜索包含"创建笔记"文字的元素。

**写法二：写 XPath 表达式（精确）**
```
locator: //android.widget.TextView[@resource-id="com.onyx.android.note:id/tv_create"]
```
XPath 可以通过 Appium Inspector 工具获取。

### action 列 — 动作类型

如果不填，程序会根据元素 key 中的关键词自动推断。手动填写可以覆盖自动推断。

| 值 | 含义 | 用在什么场景 |
|---|---|---|
| `click` | 点击 | 按钮、菜单项 |
| `assert` | 检查存在 | 页面元素是否显示正常 |
| `assert_not` | 检查不存在 | 某个元素不应该出现 |
| `assert_text` | 检查文本内容 | 验证显示的文字是否正确 |
| `assert_toast` | 检查 Toast 提示 | 验证弹出的提示信息 |
| `input` | 输入框 | 需要输入文字的地方 |
| `long_press` | 长按 | 需要长按的元素 |
| `dismiss` | 关闭弹窗 | 引导弹窗、提示弹窗 |

### index 列 — 元素序号

当页面有多个相同文字的元素时，用 index 指定第几个（从 0 开始）。

```
locator: //*[@resource-id="com.onyx.android.note:id/tv_title"]
index: 2          → 取第 3 个匹配的元素
```

### overrides 列 — 不同设备的适配

不同设备上同一个元素可能长得不一样，用这个列来适配。

**格式：** 每行一条规则，用 `：`（中文冒号）分隔条件和值。

```
条件格式：
  阅读器               → 仅在阅读器设备上
  平板                 → 仅在平板设备上
  国内                 → 仅在国内设备上
  海外                 → 仅在海外设备上
  4.2                  → 仅在 4.2 版本上
  !4.2                 → 在非 4.2 版本上
  阅读器, 国内          → 同时满足阅读器和国内

值格式：
  skip                 → 这个设备上跳过这个元素
  //xpath表达式         → 替换定位器
```

**示例：**

```
overrides:
阅读器: //android.widget.TextView[@resource-id="com.onyx:id/btn"]
海外: skip
!4.2: skip
```

含义：阅读器上用另一个 XPath；海外设备跳过此元素；非 4.2 版本也跳过。

### checks 列 — 一次检查多个元素

当一个"检查XXX"步骤需要同时验证页面上多个元素时使用。

**格式：** 用单独一行的 `|` 分隔每个子元素，每个子元素一行 XPath + 一行期望文本。

```
checks:
//android.widget.TextView[@text='登录']
登录按钮存在
|
//android.widget.TextView[@text='创建笔记']
创建按钮存在
|
//android.widget.TextView[@resource-id='...']
引导文案显示正常
```

程序的检查逻辑：每个子元素都必须在页面上找到，才算检查通过。

## 四、程序是怎么工作的（执行流程）

```
1. 读取 test_cases.xlsx
   ├── 解析每一行的"操作步骤" → 拆分出每一步 + 提取【】标签
   ├── 解析"前置条件" → 判断哪些用例该跳过
   └── 按优先级过滤

2. 读取 elements.xlsx
   ├── 把所有元素的 match → key 建立索引
   └── 加载每个元素的定位信息和动作类型

3. 匹配
   └── 每个步骤的【】标签 → 在元素索引中找到对应的 element_key

4. 连接设备并执行
   ├── 检查设备连接、语言、WiFi
   ├── 清理笔记应用数据（每次测试前都清干净）
   ├── 逐条执行测试用例
   │   ├── 检查前置条件 → 不符合就跳过
   │   ├── 逐步骤执行
   │   │   ├── 点击 → 找到元素 → 点击
   │   │   ├── 检查 → 找到元素 → 确认存在
   │   │   ├── 输入 → 找到输入框 → 填入文字
   │   │   ├── 长按 → 找到元素 → 长按
   │   │   └── 关闭弹窗 → 找到弹窗 → 点击关闭
   │   └── 记录通过/失败/跳过
   └── 打印测试汇总

5. 输出结果
   └── 打印"通过=X, 不通过=Y, 跳过=Z"
```

## 六、怎么运行测试

### 方式一：PyCharm 中直接跑（最常用）

在 PyCharm 中打开 `test_excel_runner.py`，右键 → **Run**。

- 会自动连接设备、清理数据、执行 `test_cases.xlsx` 中的 P0 用例
- 结果打印在控制台

### 方式二：命令行跑指定用例

```bash
# 跑所有 Excel 用例
pytest Note_Automation/Test_local_notes/test_excel_runner.py -s

# 只跑 P0 用例（默认就是）
# 在 test_excel_runner.py 中修改 PRIORITY_FILTER = "P0"

# 跑旧版 Python 测试用例（按标签）
pytest -m "china and increment"
```

### 方式三：生成可视化报告

```bash
python Note_Automation/Test_local_notes/run_test_report.py
```

会自动打开浏览器展示 Allure 报告（包含截图、步骤耗时等）。

### 运行前提

1. 设备通过 USB 连接电脑，开启 USB 调试
2. Appium 服务已启动（或配置了自动启动）
3. 设备语言为中文（zh-CN）
4. 设备已连接 WiFi

## 七、常见问题

**Q: 步骤中写了 `【xxx】` 但程序说"未匹配到任何元素"？**

A: 检查 `elements.xlsx` 中是否有 match 列等于"xxx"的元素。注意：
- match 要和 `【】` 里的文字**完全一致**（包括标点符号）
- 如果文字写错了或者没定义，就会匹配失败
- 匹配失败的步骤会被**跳过**（不会导致用例失败）

**Q: 用例明明失败了，为什么汇总显示"通过"？**

A: 可能有两种情况：
- 测试还没跑到那一步就中断了（比如应用没启动成功）
- 步骤的"预期结果"还没被校验（目前预期结果列仅作文档用，不参与自动化校验）

**Q: 怎么让一条用例只在平板上跑？**

A: 在前置条件列（I 列）加上 `【平板设备执行】`。程序会自动判断当前设备类型，不符合就跳过。

**Q: 多个用例共用同样的步骤怎么写？**

A: 目前不支持步骤复用，每条用例在 Excel 中独立一行。如果步骤类似，可以复制行再修改。

**Q: 为什么跑完后 Excel 文件没有被修改？**

A: 设计如此。测试结果只打印在控制台日志中，不会写回原始 `test_cases.xlsx`。这样避免多人协作时的文件冲突。

**Q: 程序报错"元素在 3 次重试后仍失败"？**

A: 说明页面上找不到这个元素。常见原因：
- 页面还没加载完 → 程序会等，但有时仍然超时
- 元素在当前页面上不存在（比如还在上一页）
- 定位表达式写错了
- 检查截图（程序会自动截图保存到 `artifacts/screenshots/` 目录）

**Q: 怎么添加新的设备型号？**

A: 在 `Devices_list/devices/` 目录下找到对应的 YAML 文件，按格式添加一行。需要知道设备的 platform、region、type、size、colour 属性。
